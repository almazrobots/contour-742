# ADR-0007. Набор «Хакатон» в бакете

## Контекст

`yandex:Загрузки/Хакатон` — официальный пакет организатора ЛЦТ (15.09.2026): 13 архивов, каждый в tar и zip
(zip — в `_ZIP_ДУБЛИ/`), по описям 10 037 файлов, 83,7 ГБ, уникальных по SHA-256 — 8 456. Режим набора нигде не
был записан: ADR-0002 касается только `corpus-ABC` (на Диске от него остался один README), ADR-0004 п. 2 запрещает
класть корпус в бакет без шифрования. Работа с набором шла поштучно и каждый раз заново: архив скачивался или
читался потоком целиком ради одного объекта.

Решение владельца 27.09.2026 (дословно по смыслу): «в бакет сложить всё, что сейчас есть в папке хакатона,
архивы распаковать и организовать; выбрать один комплект; сделать один раз, чтобы дальше работать с готовой базой
файлов — агент берёт файлы из бакета, отмечает у себя статус и использует».

## Решение

1. **В бакет `nadzorium` кладётся весь набор, распакованный,** включая вложенные архивы (zip/rar/7z/tar раскрываются
   тем же потоком, глубина ≤ 3). Комплект — **tar** (zip — дубли; tar читается потоком без произвольного доступа).
   `РАЗМЕЧЕННЫЙ_*.zip` есть только в zip — читаются потоком так же.
2. **Шифр — на клиенте, формат API** (ADR-0006: AES-256-GCM, `nonce ‖ шифротекст ‖ тег`, ключ
   **свой ключ** `.secrets/nadzorium-corpus-encryption.key`), ключ объекта — `corpus/hackathon-2026-09/blobs/<sha256
   открытого текста>`. Этим выполнено условие п. 2 ADR-0004; одинаковый файл лежит один раз. Ключ отдельный от мастер-ключа
   блобов API, потому что тот лежит и на публичном демо hk-ru (OWASP T-140 E2-H1): утечка демо не раскрывает набор.
   Ключ корпуса — только на маке, копию хранит владелец (потеря ключа = перезаливка из архивов Диска). API прочтёт
   набор, когда `BlobStore` научится выбирать ключ по префиксу (T-144).
3. **Каталог** (архив, путь, вложенность, размер, sha256) — вне git (`~/Documents/2026.09 ЛЦТ НАДЗОРИУМ/Хакатон/_S3/`)
   и шифрованным объектом `corpus/hackathon-2026-09/catalog.jsonl` в бакете. В репозиторий — только инструмент
   `scripts/corpus-to-s3.py` и статистика без путей.
4. **Перенос — только очередью `translog`** (правило №1): шифротекст партиями ≤ 2 ГБ во временной папке, `enqueue
   --kind move` → сверка каждого объекта по размеру в бакете. Открытый текст на диск не пишется, кроме временной
   копии вложенного архива на время его разбора.
5. **Демо и тесты — по-прежнему синтетика** (ADR-0002 п. 2 остаётся в силе для репозитория, скриншотов и публичных
   материалов). Бакет приватный; доступ — ключ `nadzorium-s3` и ключ шифрования, оба вне git.

## Последствия

- Любой агент берёт файл так: `scripts/corpus-to-s3.py ls --grep …` → `get <sha256> -o файл` (расшифровка и сверка
  sha256), отмечает работу `mark <sha256> <статус>`.
- Удалить объекты сервисный аккаунт не может (`storage.uploader`); ошибочная заливка убирается владельцем в консоли.
- Регистрация объектов и разделов в базе (E6) и раздел «Объекты» — задачи T-143…T-147 плана T-142.
