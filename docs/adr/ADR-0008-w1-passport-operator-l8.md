# ADR-0008. Волна W1: паспорт, оператор, понижающий слой

## Контекст

Каталог TO-BE (`docs/research/TO-BE-операции-сравнения.md`, §16–17) относит к волне W1 47 параметров Матрицы.
Сейчас в коде два пути сравнения:

- **лексический** (`domain/compare.ts`, `evaluate`): одна лучшая строка на стадию, правило `param.compare` из `matrix.json`.
  Путь закрывает все 132 параметра, но без приоритета источников, отсева и provenance;
- **паспортный** (`domain/class-param.ts`, `domain/quantity-param.ts` + `data/seed/passports/M-*.json`): все упоминания,
  приоритет разделов (VER-15), комплект по шифру (LNK-01), отсев с причиной, противоречие внутри стадии (CMP-30),
  provenance (DEC-01). По нему идут М-001…М-005 и М-023; качество М-023 измерено (T-129, T-130).

W1 по объёму — это перевод 47 параметров на паспортный путь и шесть новых видов операторов.

## Решение

1. **Параметр = паспорт (данные) + оператор (чистая функция).** Новый параметр — это JSON в `data/seed/passports/`,
   а не код. Код появляется только для нового вида оператора: `domain/<вид>-param.ts` по образцу `class-param.ts`,
   и ML-экстрактор `ml/inspector_ml/<вид>_mentions.py` по образцу `class_mentions.py`. Вид паспорта — ветка
   `value.kind` и `extractor.kind` в `domain/passport.ts` (discriminated union): `ordinal`, `quantity` уже есть,
   W1 добавляет `category` (CMP-05), `aggregate` (CMP-10/07), `layers` (CMP-21) по мере задач.
2. **Ворота L6, L8 и CMP-29 — общий понижающий слой** `domain/verify-l8.ts`, который применяется к результату
   **любого** оператора после него и может только понизить статус (каталог §12). Оператор не знает о L8,
   L8 не знает об операторе. Точка подключения — одна строка в `services/inspections.ts` после вычисления `ev`.
3. **Шкалы и справочники — данные.** Шкалы классов (§20 каталога), канон материалов и таблица аналогов — в
   `data/seed/scales.json` и `data/seed/analogs.json`, читаются паспортами; нормализация ML (NRM-03/04/06/11) —
   таблица алиасов в паспорте, а не код под каждый параметр.
4. **Качество меряется мутациями до реальных объектов.** Генератор MUT-01…08, 11, 12, 17, 18 (§15.1) строит пары
   векторных PDF «ПД → РД» на синтетике `ml/synth`, истинная метка известна заранее. На каждый оператор не меньше
   100 положительных и 100 отрицательных примеров. Регресс-гейт QA-07 сравнивает с базовой линией в репозитории.
5. **Формат разбора не меняется.** `PARSER_REV = 4`, `ParsedDoc`, `parse_file` — неизменны до влития кэша
   GPU-разбора T-165. Всё новое извлечение работает поверх текущего `ParsedDoc`.

## Последствия

- Параллельные ветки почти не пересекаются: каждая добавляет свои паспорта, свой файл оператора, свой экстрактор
  и свой диапазон номеров правил в `03-services.md` (план `docs/plan/W1-ПЛАН.md`). Общие точки (`passport.ts`
  union, диспетчер в `inspections.ts` и `extract.py`, `model.yaml`) — короткие вставки, конфликты решает
  координатор при влитии.
- Лексический путь остаётся для параметров вне W1 и как запасной: параметр с паспортом идёт паспортным путём.
- L8 может понизить уже принятый кандидат после пересчёта: решение инспектора переносится по отпечатку
  доказательства (OS-INSP-3.3.5–3.3.6), как сейчас.
- Цена: для каждого вида оператора нужен свой экран provenance. Общий компонент `ClassMentions.tsx` расширяется,
  а не копируется.
