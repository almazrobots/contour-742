## Находки

### RED

**OS-INSP-3.1.2: «обязательный источник» не участвует в решении.**
- `apps/api/src/domain/compare.ts`: `stageRequired()` (стр. 21) используется только для `stage_notes` (стр. 83–86). Статус MISSING_EVIDENCE ставится по количеству значений: для правил delta/equal/increase/decrease — при `used.length < 2` (стр. 128), для min/max — только когда значений нет совсем (стр. 107).
- Что из этого следует:
  - (а) порог min/max: ПД обязательна (`source_pd` задан) и загружена, но значения в ней нет, есть только РД. Результат — NEGATIVE_VERIFIED «Порог соблюдён во всех стадиях», хотя обязательного источника нет. Тест это поведение закрепляет: `domain.test.ts:213` `evaluate({door, values:[V("RD",0.9)], loadedStages: ALL})` → NEGATIVE_VERIFIED.
  - (б) delta_pct: обязательны ПД, РД и ИД, значения есть только в ПД и РД. Сравнение идёт, выходит NEGATIVE_VERIFIED или CANDIDATE, и нехватка ИД видна лишь как NO_VALUE в stage_notes.
- Связанный тест проверяет только 1 значение из 3 и 0 значений из 3. Утверждение «не считает нарушением» тоже не проверено, хотя структурно выполняется (protocol.ts:110).
- Как проверить: `evaluate({param: P({compare:{kind:"min",min:0.9}}), profile:{}, values:[V("RD",0.9)], loadedStages:["PD","RD","ID"]}).status` даёт `NEGATIVE_VERIFIED`, ожидается `MISSING_EVIDENCE`.
- Решение нужно одно из двух: либо проверять `stageRequired && loadedStages.includes(s) && нет значения` → MISSING_EVIDENCE, либо переформулировать правило ГЕРА («источников для сравнения меньше двух»).

Нет теста, что CLARIFICATION_REQUIRED срабатывает раньше, чем кандидат по значениям (например, конфликт редакций в паре с дельтой 50 %), и что комплектность проверяется раньше сравнения.
