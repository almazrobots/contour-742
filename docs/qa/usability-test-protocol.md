# Юзабилити-тест верификации на 5 инспекторах

> **Цифр здесь нет.** Документ — методика и форма. Время цикла дают живые инспекторы; система его
> только снимает. Пока теста не было, «≤ 30 минут» не подтверждено.

## 1. Цель и метрики (ТЗ 9.3.6)

| Метрика | Цель ТЗ | Как снимается |
|---|---|---|
| Полный цикл верификации протокола (132 параметра, 14 нарушений) | ≤ 30 мин у опытного пользователя | автоматически, журнал аудита, wall-clock |
| Кликов на одно нарушение | ≤ 3 | наблюдатель; по устройству экрана: подтвердить — 1, отклонить — 3, уточнить — 1 |
| Приёмка | замер на 5 инспекторах, протокол юзабилити-теста | отчёт системы + лист наблюдателя |

Вердикт по времени: цель подтверждена, если участников ≥ 5 и **каждый** завершённый цикл ≤ 30:00
(30:00 — в цели, 30:01 — нет). Медиана и доля в цели нужны для доработки, не для вердикта.

## 2. Кто участвует

«Опытный пользователь» — инспектор, который:

- не меньше года проверяет ПД/РД/ИД на объектах капстроительства;
- прошёл на стенде вводный прогон (разд. 4, шаг 2) и один тренировочный протокол, **не тот**, что в замере.

Пять разных людей — пять разных учётных записей: отчёт считает участников по `user_id`.
Одна учётка на двоих ломает счёт.

## 3. Материал

- **Только синтетика `ml/synth/generate.py`** (ADR-0002). Корпус с Яндекс.Диска на тест, в демо
  и на скриншоты не попадает никогда.
- Пакет с 132 параметрами и **14 заложенными нарушениями** — объект `OBJ-USB-132` (OS-INSP-6.5.16, T-081): все параметры
  Матрицы, 51 PDF по разделам, ключ `answer-key.json` рядом. В репозитории не хранится, генерируется детерминированно по seed:
  `cd ml && uv run python -m synth.usability_132 --seed 1 --out ../var/usability` → `var/usability/OBJ-USB-132`, загрузить целиком.
- Для тренировки берётся другой синтетический объект.

## 4. Порядок проведения

1. Стенд профиля dev, веб на порту 45810, база свежая, пакет загружен и разобран (статус READY).
   На каждого участника своя проверка (`process_id`) того же пакета.
2. Вводный прогон, 10 мин: очередь, карточка доказательства, три действия, клавиши J/K и 1/2/3,
   «Завершить». Тренировочный протокол — без замера.
3. Задание участнику, дословно: «Разберите все кандидаты в очереди: по каждому подтвердите,
   отклоните с причиной или отправьте на уточнение. Когда очередь пуста — нажмите „Завершить“».
   Подсказок по ходу нет; вопрос участника фиксируется как затык.
4. Отсчёт начинается сам при открытии экрана верификации (`VERIFICATION_OPENED`), заканчивается
   финализацией (`PROTOCOL_FINALIZED`). Секундомер не нужен.
5. Наблюдатель ведёт лист (разд. 6) молча.
6. Сразу после — анкета SUS (разд. 7), затем 5 минут свободного разговора.

## 5. Что снимается автоматически

`GET /api/v1/usability/verification-report` (супервизор, администратор):

- JSON — по каждой проверке: участник, начало и его источник, конец, wall-clock, активные минуты,
  решений, разных кандидатов, подтверждено, разделено, в цели или нет; сводка — участники,
  медиана и максимум, доля в цели, вердикт;
- `?format=md` — готовый раздел «Замеры» и «Итог против цели» для протокола ниже.

Правила замера (`apps/api/src/domain/verify-timing.ts`):

- начало — первое открытие экрана; если его нет или решение было раньше — первое решение
  (в отчёте «Источник начала: первое решение» — такой замер проверить глазами);
- конец — первая финализация после начала; без неё цикл «не завершён» и в вердикт не входит;
- **активное время — допущение, не ТЗ**: паузы длиннее порога простоя (по умолчанию 10 мин,
  `?idle_minutes=`) не засчитываются. Вердикт — только по wall-clock.

## 6. Что фиксирует наблюдатель

| № | Время | Кандидат (param_code) | Что случилось | Тип | Кликов на нарушение |
|---|---|---|---|---|---|
| | | | | ошибка / затык / вопрос / обход | |

- **Ошибка** — решение, не совпавшее с ключом ответов (`answer-key.json`), или действие не туда.
- **Затык** — пауза дольше 30 с без действия, либо участник вслух не понимает, что делать.
- **Клики** — на 3–5 нарушениях подряд, от появления карточки до ухода на следующую.

## 7. Анкета SUS

Шкала 1–5 (1 — совсем не согласен, 5 — полностью согласен).

1. Я бы хотел пользоваться этой системой регулярно.
2. Система неоправданно сложна.
3. Системой легко пользоваться.
4. Чтобы работать с системой, мне нужна помощь специалиста.
5. Функции системы хорошо увязаны между собой.
6. В системе слишком много несогласованности.
7. Большинство людей освоят систему очень быстро.
8. Системой очень неудобно пользоваться.
9. Я уверенно чувствовал себя, работая с системой.
10. Прежде чем начать работать, мне пришлось многому научиться.

Балл: нечётные — (ответ − 1), чётные — (5 − ответ), сумма × 2,5 → 0–100. Цели по SUS в ТЗ нет;
ориентир — 68 (средний по отрасли), ниже — повод разбирать затыки в первую очередь.

## 8. Доработка до целевых метрик

Цикл повторяется, пока вердикт не «подтверждена» и клики ≤ 3:

1. **Тест** на 5 участниках → отчёт системы + листы наблюдателя.
2. **Список правок**: каждый затык и каждая ошибка → строка «что мешало → правка → какая метрика
   должна сдвинуться». Правка — задача в `tasks/`.
3. **Повторный тест** после правок. Участники — другие или те же не раньше чем через неделю
   (иначе мерим память, а не интерфейс); в протоколе указывается, кто повторный.
