## Очередность съёмки

1. **Основная платформа, приоритет всей платформы:** съёмка инспекторского пути уже в работе. Зафиксировать API `c0851cc7`, UI image `e1c9dc4f` и overlay, проверить их паритет. Затем пакет/разбор → источник/сверка → решения → финализация. При доступе только к CPU снимать просмотр, изменяющие действия оставить pending.
2. **Справочники, модели, журнал/метрики и материалы:** паспорт/норма, GOLD/обучение/публикация по фактическим правам, событие/метрика, реестр/план и Trace Map. Проверять итог каждого действия, не подменять отсутствующую кнопку выдуманным интерфейсом.
3. **Расширение разметки df65e188:** structured original/ответ, контролируемые ошибки, независимый разбор и выпуск куратором. Нормальный сохранённый NO не проверяет эти ветки; сначала подтвердить UI/API и права каждого сценария.

Для каждой партии 2–3 ролика: role, fixture, UI/API revision, docs/media revision, исходное состояние, действия, сохранённый итог, дата и ограничения. Только синтетические или явно разрешённые публичные примеры. Ошибки воспроизводить в разрешённом изолированном контуре настоящего API, не ломать production. Каждое видео имеет синхронные captions, полную текстовую расшифровку, главы и читаемый постер; ресурс встраивается у нужного шага и в каталог.
