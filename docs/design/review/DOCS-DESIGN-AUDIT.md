# Аудит оформления документации — 29.09.2026

Основание: два пользовательских скриншота; read-only исходники BankImpulse (`src/app/docs/docs.css`, `layout.tsx`, `src/components/mdx.tsx`, `screenshot.tsx`, `content/docs/for-admins.mdx`); текущие `docs/user-guide/guide.css`, `navigation.json`, `scripts/user-guide.mjs`. Live URL эталона не открылся через web; выводы о внешнем виде основаны на приложенном изображении и исходниках, а не на проверке live поведения.

## Что реально расходится

| Текущее решение | Влияние | Исправление |
|---|---|---|
| Центрированный grid 270/820/220 с внешними полями | На широком экране слева большая пустота, навигация оторвана от края | Sidebar у левого края, layout шириной 100%, текст центрируется внутри оставшейся области |
| Sticky header на всю страницу | Теряется сходство с эталоном, начало статьи смещено вниз | Название базы, поиск и ссылки сайта в sidebar; статья начинается без глобальной полосы |
| Белая обведённая карточка `main` с padding 32/40 | Вложенность и рамка доминируют над содержанием | Открытая статья на светлом фоне; карточки только для отдельных callout/материалов |
| Eyebrow капсом, крупный H1 34px, группы капсом | Другой характер иерархии, тяжёлое начало | Спокойные группы; H1 28–30px, H2 24px, меньше лишних меток |
| Одинаковая плашка CPU-демо в каждой статье | Забирает внимание у конкретного сценария | Показывать ограничение рядом с действием, которого оно касается; на главной краткая общая заметка |
| Изображения только у 2 из 16 статей | Большинство сценариев не подтверждены визуально | Несколько изображений в нужных местах статьи, снимки основного рабочего интерфейса и состояний |
| `page.screenshot` — один снимок, вставка перед вторым H2 | Автор не управляет расположением иллюстрации | Явный компонент/директива изображения в содержимом, отдельный manifest активов |
| Оглавление без активного раздела | Нет текущей позиции при чтении длинной статьи | Иерархия H2/H3, scrollspy и заметный активный пункт |

## Предлагаемые параметры первого макета

Это стартовые проектные значения, а не заявление о точных пикселях live эталона.

- Фон #F4F6FA, текст #16202F, вторичный #6B7788, граница #E6EAF1, действие #2563EB; белый фон sidebar и компактных callout.
- Desktop sidebar 260–280px, статья максимум 760–840px, TOC 220–250px; колонка статьи может иметь свободные поля, sidebar всегда примыкает к левому краю.
- Отступы sidebar 16px; статья сверху 56–64px, между разделами 40–48px; основной текст 16px/1.7, описание 18px/1.5, навигация 14px/1.5.
- Сохранить шрифты продукта; Golos для текста, единый выбранный стиль заголовков. Не переносить логотип/бренд Импульса.
- Поиск 36–40px высотой, округление 10px; активный пункт спокойный голубой фон, нормальный вес текста.
- Callout: заголовок, смысловая иконка, тонкая цветная линия, радиус 12–14px; предупреждения выделяются по смыслу, а не вся статья.
- Screenshot: естественные пропорции, рамка/радиус 12px, подпись 13px, увеличение; ширина и высота в metadata для стабильного layout.
- Tablet: TOC скрывается, sidebar остаётся доступным. Mobile: кнопка меню/панель, поиск и оглавление доступны; без горизонтального скролла всей страницы.
- Общие сервисные страницы используют те же токены, навигацию, заголовки и состояния; таблица реестра получает собственный широкий шаблон вместо узкой статьи.

## Static или Fumadocs

Рекомендация для первого этапа: улучшить существующую статическую генерацию. Текущий генератор уже выпускает HTML, локальные шрифты, поиск и ссылки; такой путь даёт нужную геометрию без миграции приложения. Эталон достигает результата темой Fumadocs, но качество зависит также от редакторской структуры и снимков — установка библиотеки их не создаёт.

Fumadocs разумен, если принимаем отдельный Next/React сайт документации и долгосрочное использование MDX, дерева страниц, готовых диалогов поиска и компонентов. В проекте Надзориума нет подтверждённой текущей Next интеграции: это отдельное архитектурное решение с маршрутами, сборкой, зависимостями, развёртыванием и регрессией общей CSS темы. Оценивать его отдельной альтернативой после короткого прототипа, не включать молча в косметическую задачу.

## Пакеты для оценки и приёмки

Оценки предварительные, в рабочих днях одного специалиста, без обновления всего содержания; точный объём зависит от числа снимков/страниц и доступа к рабочему стенду.

| ID / приоритет | Задача | Оценка | Критерий приёмки |
|---|---|---|---|
| D1 / P0 | Общие токены и каркас + макет главной/длинной статьи/реестра | 1–2 | На 1440 и 1920px sidebar у края, статья без внешней карточки и global header; согласованные шрифты, интервалы, TOC; 390px без горизонтального скролла |
| D2 / P0 | Компоненты и статический генератор: callout, steps, screenshots, таблицы, служебные ссылки | 2–3 | Автор размещает несколько снимков в нужных местах; caption/alt/размеры обязательны; нет привязки вставки к «второму H2»; все страницы используют один шаблон |
| D3 / P0 | Иллюстрации и перепроверка 16 статей по настоящим сценариям | 3–5 | Матрица «статья → сценарий → снимок → версия»; покрыты инспекции, загрузка, сверка, решения, финализация, разметка, витрина, модели и журнал; названия кнопок совпадают со стендом, отсутствующие возможности явно обозначены |
| D4 / P1 | Единая навигация/поиск/TOC и оформление реестра, Trace Map, планов, отчётов | 2–4 | Переходы обратно в базу и приложение понятны; статусы/даты/версии различимы; есть пустое состояние и отсутствие результатов; одинаковые токены во всех публичных служебных шаблонах |
| D5 / P0 | Визуальная приёмка и проверка сборки | 1–2 | Скриншоты desktop/mobile для трёх шаблонов; клавиатурная навигация и активное оглавление; нет битых локальных ссылок/изображений; ограничения демо не выдают себя за рабочие возможности |

Первое исполнимое решение: D1 задаёт общую систему и три примера, затем D2 и редакторская подготовка D3 идут параллельно. D4 наследует утверждённые компоненты; D5 завершает интеграцию. Альтернатива Fumadocs требует отдельной оценки миграции и не заменяет D3/D4/D5.

## Обязательная отсечка качества коммерческой базы знаний

Приёмка проходит по наблюдаемым результатам; одна перекраска CSS её не удовлетворяет. Общий первый образец — «Разметка данных» со снимками и видео; второй — «Сверка и решение инспектора». Оба проверяются на соответствующем рабочем/демонстрационном стенде до массового переноса шаблона.

- Статья содержит роль, условия начала, последовательность действий, ожидаемый результат, ошибки и восстановление, реальные ограничения; каждый значимый переход подтверждён актуальным снимком с подписью и alt.
- Видеоурок доступен в отдельном каталоге и встроен в соответствующую статью; есть длительность, содержание, captions, текстовый transcript и управление с клавиатуры; autoplay отсутствует.
- Одна оболочка покрывает руководство, реестр документов, планы, отчёты и каталог видео; компоненты callout, steps, screenshot, video, table и metadata задаются централизованно.
- Для каждой статьи и видео указаны владелец, версия продукта, дата проверки и статус актуальности; работающие сценарии, демо и планы явно различимы. Обновление интерфейса включает проверку связанных материалов.
- Поиск возвращает конкретную статью/сценарий, показывает отсутствие результатов; у длинных статей работает активное оглавление. На каждом служебном шаблоне доступен путь к базе знаний и приложению.
- Доступность проверена: видимый focus, порядок tab, семантические заголовки, контраст уровня WCAG AA, alt, captions/transcript, reduced motion; основные действия доступны без мыши.
- Визуальная приёмка включает реальные снимки главной, образцовой статьи, реестра и видео на 390/768/1440/1920px; нет обрезанного текста, перекрытий, горизонтального скролла страницы и скачков от загрузки медиа.
- Сборка выявляет битые ссылки, отсутствующие media и обязательные metadata; проверка сценария подтверждает совпадение текста/снимков/видео с текущими кнопками и результатами стенда.
- Массовая публикация начинается только после прохождения образцовой статьи и всех четырёх шаблонов; найденные дефекты фиксируются с владельцем и проверяемым исправлением.

Фреймворк выбирается по стоимости сопровождения, качеству поиска/авторинга и совместимости со сборкой; миграция ради популярности инструмента не является задачей. Видеопроизводство, редакторская перепроверка и автоматические проверки требуют отдельных оценок сверх предварительных D1–D5.
