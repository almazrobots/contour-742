- accepted у ADR и as-built у state-machine не означают ready для пользовательского сценария. Статусы источника, актуальности медиа и выполнения задач должны быть отдельными.
- `docs/plan/*` в текущую публикацию не входит. TOP-20-FINAL — draft; RESET от 27.09 также draft и меняет прежнюю шкалу/порядок. Есть proposed/proposal/in-progress. Подтверждённый текущий план unknown; имя FINAL и дата файла не подтверждают current.
- Старые планы включать только через будущую явно разрешённую историю; всю папку автоматически не публиковать. Приватные ответы, исходный корпус и payload не входят в список ресурсов.
- Для записанного сценария известны df65e188, дата и синтетический контур. Остальные сценарии требуют live-проверки. Git HEAD, site_revision, дата сборки и docs_published_at не заменяют сведения о развёрнутом UI и результате действия.
- Каталог материалов отличается от `apps/web/src/pages/Files.tsx`: это рабочий реестр через API. Его переделка не входит в первый scope документации.

## Сборка и runner

- `scripts/demo-docs.mjs` очищает выходной каталог и собирает все материалы и guide. Markdown проходит md2html + page(); самостоятельные HTML копируются целиком. Обновление только doc.css не унифицирует их оформление.
- `scripts/demo.sh publish` собирает материалы с публикацией данных; docs читает прежний publication.json, пересобирает материалы и заменяет серверный каталог. Эти пути не подтверждают UI-релиз и не переключают весь docs транзакционно.
- `scripts/runner/publish-user-guide.mjs` проверяет schema nadzorium-user-guide.v1, число страниц, имена файлов и отсутствие symlink. Через staging/rename заменяет guide, сохраняет старый guide и копии index/Trace Map, добавляет ссылки на руководство при отсутствии; при ошибке восстанавливает прежние файлы. Сведения publication.json не меняются.
- Runner проверяет форму артефактов, но не соответствие UI, безопасность содержимого или согласованность media-release. Успешная публикация не является содержательной приёмкой.

## Первый scope и минимальный путь общей оболочки

1. Общая оболочка guide, index и Markdown-материалов: локальные токены/CSS, навигация, метаданные, читаемый текст, оглавление и ссылки через явный манифест; сохранить URL. Первый принятый образец — инструкция с проверенным безопасным скриншотом.
2. Ввести контракт scenario_id/ui_revision/docs_revision/media_revision/role/fixture_id/checked_at/check_id/outcome; разделить ready/stale/draft и статус исходника. UI-версию получать из подтверждённого развёрнутого релиза. До подтверждения показывать unknown.
3. Добавить план через явный подтверждённый источник; иначе показать «Действующий план не подтверждён». Не публиковать старый proposed как current.
4. Pipeline/Architecture и дизайн-систему адаптировать в исходниках/генераторах отдельными партиями. BI сохраняет маркировку макета; результаты — даты прогонов и ограничения.
5. Trace Map оставить широким интерактивным документом. Общий бренд/ссылки и токены внедрять через scripts/trace-map.mjs; не переписывать body автоматически и не сжимать карту до колонки статьи. Сохранить coverage/audit/map/doc/detail/gaps/catalog/metrics, query-ссылки, поиск, панель текста, подсветку и J/K.
6. Один ролик опубликован, воспроизведение проверено live; второй подготовлен live-проверен в пределах этой партии. Следующий scope — по 2–3 новых сценария за партию; captions, индексируемый transcript и проверка совпадения UI/текста/кадров обязательны. Публиковать только безопасные разрешённые артефакты.

Приёмка первой партии: сохранность маршрутов, поиска и оглавления; разрешённые ресурсы; честные статусы/версии; desktop/mobile и клавиатура. Trace Map проходит самостоятельную регрессию при каждом его изменении.
