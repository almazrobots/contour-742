## Корпус на раннере

Корпус «Хакатон» — на раннере, **только чтение** (согласовано с T-165 28.09): `/opt/corpus` (blobs/, tree/,
catalog/*.jsonl) и кэш разбора r4 `/opt/inspector/cache` (`parsed-<sha>-r4`). Ничего там не писать и не переименовывать,
копий и жёстких ссылок в `/opt/w1-gate` не делать, в Redis стенда nadzorium-gpu не писать. Наружу (git, логи раннера,
чаты, Telegram) — только агрегаты по коду параметра и коду объекта (POL-17, LOS-3A, ALT-79B…): без текстов, цитат,
имён файлов, страниц, ФИО, картинок (ADR-0002). Разбор ошибок — только на сервере в `/opt/w1-gate/eval/<волна>` (700).
Прогон — через remote-run под лимитом памяти волны, nice 19, пока идёт разбор T-165; VLM и GPU — только окном от T-165.
Тесты, репо и демо — по-прежнему только синтетика.

## Тимлиду волны — пять строк

1. Код правишь на маке в своём worktree, **ничего не запускаешь локально**; всё — `scripts/remote-run.sh` из ветки
   `feat/w2-…` или `feat/w3-…` (волна берётся из имени ветки, иначе `--wave w2`).
2. Лёгкое (тест по файлу, tsc, trace) — `--light`, отладка незакоммиченного — `--wip`; гейт и мутации — по коммиту, полоса heavy
   твоей волны (пока разбор T-165 идёт — закрыта, код 75).
3. Потоки мутаций — `--concurrency \$W1_THREADS`; отчёты — `--get <путь>`, логи — `/opt/w1-gate/logs/`.
4. Стенд ветки — `scripts/remote-run.sh stand up [ветка]` (T-183), с мака — `ssh -N -L 45810:127.0.0.1:45810 root@158.255.3.179`.
5. Не трогать GPU, `vllm-*`, стенд T-185; `/opt/corpus` и кэш r4 — только чтение и только агрегаты наружу (раздел выше).
   Команды подробно — `docs/ops/REMOTE-RUNNER.md`.

## Как добавить вид параметра (T-186, OS-INSP-7.1.20–7.1.24)

1. API: модуль `apps/api/src/domain/kinds/<вид>.ts` — `registerKind({ kind, value, extractor, evaluate, mentions?, spec?, quote? })`
   из `domain/param-kinds.ts`; из `passport.ts` — только `import type`.
2. API: одна строка `import "./<вид>.ts";` в `apps/api/src/domain/kinds/index.ts` — по алфавиту (ветки не сталкиваются на одной строке).
3. ML: функция `(doc, spec) -> list[Extraction]` в своём модуле + одна строка `register("<вид>_mentions", функция)` в конце
   `ml/inspector_ml/extractor_kinds.py` (по алфавиту). Часть паспорта (T-174) берёт извлекатель так же — `way_by_kind(kind)`.
4. Схема паспорта, диспетчер `recompute` и выбор извлекателя в `extract.py` не правятся; гипотезы вида пишутся общим путём
   (`suspicionRecord`), своя цитата опоры — `quote`. Незнакомый вид в паспорте — отказ загрузки с именем вида.
5. Образец — `apps/api/tests/kinds/t-presence.ts` и `ml/tests/test_extractor_kinds.py`:

```ts
// apps/api/src/domain/kinds/presence.ts
export const presence = registerKind({
  kind: "presence", value: z.object({ kind: z.literal("presence"), words: z.array(z.string()) }),
  extractor: z.object({ kind: z.literal("presence_mentions"), anchor: z.string() }),
  evaluate: ({ param, passport, mentions, loadedStages }) => evaluatePresence(param, passport, mentions, loadedStages),
});
```

**EXTRACT_REV** (`ml/inspector_ml/extract.py`, ключ кэша /analyze) в ветках волн не поднимается: его поднимает только
вливающий в main, ровно +1 на влитие, с записью в комментарии, что вошло. Так две ветки не выдают один номер за разную логику.
