## Как работа устроена сейчас (AS-IS)

1. **Кто.** Инспектор государственного строительного надзора (ГрК РФ ст. 54) проводит
   камеральную проверку документации объекта капитального строительства. Помимо него —
   администратор (нормативная база, пороги), ML-инженер и куратор данных (дообучение).
2. **Вход.** Три массива документов одного объекта: проектная (ПД, разделы по ПП РФ № 87),
   рабочая (РД, комплекты по ГОСТ Р 21.101) и исполнительная (ИД, по Приказу Минстроя № 344/пр).
   Документы — PDF (в т. ч. сканы), DOCX, XML; бывают несколько редакций одного документа.
   Каждый комплект сопровождается реестром файлов (object_id, doc_stage, discipline,
   document_code, revision, approval_status, approval_date, листы, predecessor/successor,
   подпись) — без реестра пакет уходит в CLARIFICATION_REQUIRED (SRC-INSP-03).
3. **Что проверяют.** 132 контролируемых параметра Матрицы (площадь застройки, класс бетона,
   ширина эвакуационных дверей …). Для каждого — где его искать в ПД, РД и ИД, и логика
   расхождения («дельта > 1 %», «понижение класса», «< 0,9 м»).
4. **Как проверяют.** Сравнивают значения по последней применимой утверждённой редакции.
   Устаревшая редакция эталоном быть не может. Нашли расхождение — фиксируют доказательство:
   лист, зона на листе, шифр, редакция (SRC-INSP-04 показывает, как это выглядит на чертежах).
5. **Решение.** Только инспектор признаёт нарушение. Уровень риска — очерёдность проверки,
   не юридическое действие. Отсутствие документа — не нарушение, а пробел комплектности.
6. **Выход.** Протокол проверки с разделами: статус загрузки, тип проверки, комплектность,
   кандидаты, подтверждённые нарушения, проверенные отрицательные, гипотезы. Подтверждённое
   уходит в ИАИС «РиН». Дальше — предписание в пределах полномочий инспектора (вне системы).
7. **Обучение.** Решения инспектора — эталонные метки (GOLD) для дообучения модели;
   публикация новой модели — только после приёмки и подписи ответственного.

## Боли, которые называет постановка

- Ручная сверка трёх массивов по 132 параметрам долгая: цель ТЗ — полный цикл верификации
  одного протокола ≤ 30 минут, ≤ 3 кликов на нарушение.
- Путаница редакций: сравнение не с той редакцией даёт ложное нарушение.
- Нарушение без доказательства на листе не воспроизводимо и не годится ни для
  предписания, ни для обучения.
