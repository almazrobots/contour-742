## Выберите режим

Рабочий GPU-стенд обрабатывает новые документы. CPU-копия показывает согласованный снимок и должна запускаться с `INSPECTOR_READONLY=1`: запрет изменения проверяет сервер, а не только интерфейс. CPU-копия с исторической БД ещё не гарантирует доступность оригиналов: нужны отдельные права S3, ключ расшифрования и достаточное место под кэш.

## Новый GPU-стенд

Нужны Linux x86-64, root, systemd, cgroup v2, Python 3, OpenSSL, curl, Docker Engine с Compose/Buildx, NVIDIA driver >=580 и Container Toolkit. Резерв: одна свободная GPU от 22 GiB, 32 GiB RAM, 80 GiB диска плюс документы. Порт Reader 127.0.0.1:8000 должен быть свободен. Для первой сборки нужны Docker Hub, PyPI/npm, Hugging Face и ModelScope.

Проверьте SHA-256 архива по переданному release manifest и распакуйте его в отдельный каталог. Из корня исходников:

```sh
sudo python3 scripts/platform-start.py --state /opt/inspector-platform
```

Стартер включает настоящий ClamAV до сохранения загрузок. Сигнатуры хранятся в отдельном Docker volume и обновляются freshclam; первоначальные сигнатуры есть в закреплённом образе. ClamAV работает без root, имеет предел3GiB RAM и2CPU. Дождитесь healthy: недоступный сканер отклоняет загрузку, проверка молча не выключается. Нужен HTTPS-доступ к зеркалу сигнатур. После старта проверьте реальное обновление и дату базы; отсутствие обновлений требует диагностики.

Без настройки хранилища это локальный `fs`-стенд. Для GPU-поставки с S3 передайте отдельные credentials и исходный ключ шифрования:

```sh
sudo python3 scripts/platform-start.py --state /opt/inspector-platform \
  --s3-env /secure/api-s3.env --s3-key-file /secure/corpus-encryption.key \
  --s3-prefix platform/instance/blobs/ \
  --s3-read-prefixes corpus/hackathon-2026-09/blobs/
```

Файл credentials содержит `YC_S3_ENDPOINT`, `YC_S3_REGION`, `YC_S3_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, имеет права `0600` и передаётся отдельно. API-аккаунт читает и записывает объекты, без удаления. Все префиксы в команде должны использовать переданный ключ шифрования. На повторном запуске того же state S3 сохраняется и без этих опций; потеря секрета или несовпадение настроек вызывает ошибку, а не возврат к `fs`.

Повторите ту же команду для повторного запуска. State должен находиться вне исходников; он сохраняет БД, конфигурацию и ключи. `--prepare-only` подготавливает конфигурацию; `python3 scripts/platform-start.py --help` показывает остальные опции. Стартер создаёт TLS CA/сертификаты и ключ шифрования оригиналов, закрепляет модели, применяет миграции и проверяет ревизию API. Первая сетевая загрузка моделей отдельно не измерена; при приёмке использован pinned cache. Judge по умолчанию off.

UI: `https://127.0.0.1:49443`. CA: `/opt/inspector-platform/tls/ca.crt`. Доверенный внешний домен и сертификат настраивает оператор после локальной проверки. При восстановлении не генерируйте новые ключи для старых зашифрованных оригиналов.

## Логины и получение пароля

| Логин | Роль | Создание |
|---|---|---|
| inspector | Инспектор | Пустая БД, dev-профиль |
| supervisor | Супервизор | Пустая БД, dev-профиль |
| admin | Администратор | Пустая БД, dev-профиль |
| curator | Куратор | Пустая БД, dev-профиль |
| ml | ML-инженер | Пустая БД, dev-профиль |
| verifier или назначенный логин | Верификатор | Отдельно создаёт администратор; автоматического verifier нет |

Это пять демо-учёток dev-профиля, а не обязательные учётки любой восстановленной БД или production-профиля. На свежем стенде пароль хранится в `/opt/inspector-platform/secrets/demo_password`; оператор передаёт его владельцу через защищённый канал или приватный файл с доступом 0600. В стандартном Compose этот файл монтируется как `/app/var/demo-password.txt`. При самостоятельном первоначальном dev-развёртывании поддерживается `INSPECTOR_DEMO_PASSWORD` из защищённого окружения. Не записывайте значение в документацию, Git, команды shell history или отчёты. Изменение env после создания users не меняет существующие пароли.

Администратор создаёт отдельного верификатора через `POST /api/v1/admin/verifiers` с login, name и password длиной от 12 символов в авторизованной сессии. На CPU readonly создание запрещено. Для исторической БД получить действующие доступы у её владельца; не сбрасывать их повторным seed.

## Готовность и версия

```sh
curl --fail --cacert /opt/inspector-platform/tls/ca.crt https://127.0.0.1:49443/health
```

Проверьте revision, состояние ML и поле ukep. В проверенном dev-профиле ukep.mode=off и qualified=false. Успешный HTTP health не заменяет readiness всех зависимостей: проверьте состояние контейнеров, Reader health на loopback:8000, вход нужной ролью, открытие оригинала, очередь и новый малый процесс до четырёх экспортов. На CPU проверьте открытие исторического оригинала и 403 при попытке записи. Ревизию работающего API сверяйте с release manifest; новые страницы документации не меняют runtime revision.
