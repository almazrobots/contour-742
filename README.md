# Инспектор ИИ — пакет развёртывания

Исходный код: `007c0b6354703d93eab90cb18da8b6a2d8d1af82 (runtime verification: 9b5cd9a7; later changes: documentation only)`. Это экспорт выбранных файлов стабильного кандидата; история разработки не входит в поставку; приватные данные и секреты хранятся отдельно у владельца. `SOURCE_REVISION` указывает происхождение кода, а не SHA первого коммита нового репозитория.

В кодовый пакет входят справочники, синтетические тестовые данные и примеры. Реальный корпус, дампы пользовательской БД, приватная разметка, резервные копии, пароли, S3 credentials и ключи расшифрования в репозиторий не входят. Существующие оригиналы хранятся в S3; для их подключения нужен отдельно переданный разрешённый доступ и соответствующий ключ шифрования. Организаторы могут загрузить собственные документы после развёртывания.

Приватные резервные копии текущих результатов и конфигурации остаются у владельца на MacBook/в хранилище. Они не являются обязательной зависимостью чистого запуска и не передаются автоматически вместе с кодом. Скачиваемые модели загружаются стартером по закреплённым ревизиям.

Рабочий репозиторий разработки, история веток, переписки Claude/Codex и журналы агентных сессий не являются материалами сдачи. Репозиторий `contour-742` пока приватный; открытие доступа выполняется отдельно владельцем перед сдачей.

## Запуск

Целевая машина: Linux x86-64, root, systemd, cgroup v2, Python 3, OpenSSL, curl, Docker Engine с Compose и Buildx, NVIDIA driver >=580 и NVIDIA Container Toolkit. Нужны одна свободная GPU от 22 GiB, 32 GiB доступной RAM, минимум 80 GiB свободного диска плюс место под документы. Порт Reader 127.0.0.1:8000 должен быть свободен. Доступ к Docker Hub, PyPI/npm, Hugging Face и ModelScope нужен для первой сборки/загрузки.

Из корня распакованного пакета:

```sh
sudo python3 scripts/platform-start.py --state /opt/inspector-platform
```

Повторите ту же команду для повторного запуска с сохранением данных и ключей. Каталог состояния обязан находиться вне исходников. Не удаляйте его и не создавайте заново утерянные ключи: восстановите полную согласованную резервную копию. Стартер собирает три образа, скачивает закреплённые модели, создаёт секреты/CA, запускает Reader и сервисы, применяет миграции и проверяет ревизию API.

Интерфейс: https://127.0.0.1:49443. CA: `/opt/inspector-platform/tls/ca.crt`; пароль тестового профиля: `/opt/inspector-platform/secrets/demo_password`. Учётные записи и роли соответствуют стандартному GPU-профилю; они создаются приложением при первоначальном запуске. Секреты не публикуются. Внешний домен настраивается отдельно после проверки доступа.

`--prepare-only` только готовит конфигурацию. `--images <private-images.json>` использует уже имеющиеся immutable образы той же исходной ревизии. `--external-reader-container` и `--reader-controller` нужны только для испытания с существующим Reader; такой тест не подтверждает чистую установку. Все опции: `python3 scripts/platform-start.py --help`.

## Проверенный режим S3

Для подключения отдельного аккаунта API и сохранённого ключа корпуса запускайте:

```sh
sudo python3 scripts/platform-start.py --state /opt/inspector-platform \
  --s3-env /secure/api-s3.env --s3-key-file /secure/corpus-encryption.key \
  --s3-prefix platform/instance/blobs/ \
  --s3-read-prefixes corpus/hackathon-2026-09/blobs/
```

Credentials передаются отдельно, файл0600. Одинаковый ключ шифрования должен подходить ко всем указанным префиксам. Стартер включает настоящий ClamAV до сохранения. Проверка полного S3-процесса подтверждает функциональность; шифрование тома БД, непрерывный backup, мониторинг и внешние РиН/УКЭП перечислены отдельно среди открытых требований.

## Закреплённые зависимости и модели

JavaScript: `pnpm-lock.yaml`, `packageManager` в `package.json`, установка с `--frozen-lockfile`. Python: `ml/uv.lock`, установка с `uv sync --locked`. Базовые Docker-образы и сервисы закреплены digest в Dockerfile и `deploy/stand/images.env`; системные пакеты, устанавливаемые через apt/apk upgrade, не образуют побитово воспроизводимую сборку. Для точного повторного развёртывания сохраняйте итоговые образы и `images.json` отдельно.

Reader: PaddlePaddle/PaddleOCR-VL-1.5, revision `2a4195faa5e7914c12f2fc601d72c81caf8d2da5`. Judge: Qwen/Qwen3.5-9B, revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`. Стартер загружает обе модели; Judge phase по умолчанию **off**. Версия vLLM закреплена digest в стартере. PP-OCR веса имеют URL и SHA-256 в `ml/models.yaml` и `ml/Dockerfile`; embedding MiniLM закреплён ревизией и SHA-256 в Dockerfile. Большие скачиваемые веса не входят в архив. Нестандартные веса и соответствующие лицензии сохраняются отдельным приватным артефактом.

`ml/eval/seals` содержит только SHA-256, роли файлов и итоговые метаданные скрытого теста; эти manifests обязательны для защиты от использования закрытой разметки и запуска API. Оригиналов и ответов разметки здесь нет.

## Границы доказательств

Наличие пакета не доказывает чистый запуск, качество по всем 132 параметрам, полный Judge, восстановление истории или доступность публичной CPU-копии. Отчёт приёмки поставляется отдельно и должен связывать каждую проверку с исходной ревизией и SHA-256 этого архива. Неизвестные исторические версии моделей/run/job должны оставаться null/unknown. GPU-стенд после передачи не выключать и не удалять.

Репозиторий поставляется без истории разработки. Исходники, синтетические тесты, автоматизированные acceptance/restore/fault helpers и требования включены. Проверки качества на реальном корпусе требуют отдельно предоставленных авторизованных оригиналов и разметки; отсутствие этих приватных fixtures не означает отказ развёртывания. Набор `ml/eval/w1_real_sources.json` очищен до пустых mappings с явным пояснением; замены реальных ответов синтетическими нет. Подробности преобразований — `EXPORT_MANIFEST.json`.

## Эксплуатационная база знаний

После запуска: `/docs/index.html` и `/docs/guide/deployment.html`. В web image включены 22 страницы: роли/логины, получение паролей, отдельный S3 service account, ключи и восстановление. Исходники: `docs/user-guide/`. Trace Map и исторические публикационные материалы поставляются отдельно; в автономном пакете их ссылки отмечены как отсутствующие. CPU доступ к оригиналам требует отдельной настройки и не обещается готовым.

## Исторические доказательства

Реестр аудитов поставляется как сохранённая инвентаризация исходной разработки. Исторические SHA — идентификаторы происхождения; история и ссылки на приватные ревизии не входят в поставку. Повторная генерация в чистом репозитории не восстановит эту историю и обозначит недоступные основания как неизвестные.
